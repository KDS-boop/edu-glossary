# P6.3 — Pagefind Search Analytics Instrumentation

## Scope

Adds privacy-minimizing events for the Pagefind Component UI search boxes already present in the header and homepage hero. This change does not add a new tracker, dependency, or tag container and does not change `robots.txt` or the Cloudflare Content Security Policy.

## Events emitted to the existing Google Tag Manager `dataLayer`

| Event | When emitted | Parameters |
|---|---|---|
| `eduglossary_search` | The Pagefind `search` event fires for a query of at least 3 characters and the input remains unchanged for 1.2 seconds | `search_instance`, `search_query_length`, `page_path` |
| `eduglossary_search_zero_results` | The rendered Component UI shows a visible zero-results state matching the current query | `search_instance`, `search_query_length`, `page_path` |
| `eduglossary_search_result_click` | A result link in either search component is clicked | `search_instance`, `search_result_type`, `search_result_position`, `search_result_is_subresult`, `result_path`, `page_path` |

`search_instance` is `header` or `hero`. `search_result_type` is `glossary`, `article`, or `other`. Result paths are recorded as same-origin pathnames only.

## Privacy and data handling

- Raw search text is used only in browser memory for debouncing and matching the visible zero-results status. It is never added to these event payloads.
- Query length is recorded instead of the actual query.
- Queries shorter than 3 characters are not tracked as search events.
- The instrumentation reuses `window.dataLayer`; it does not replace an existing data layer.
- Zero-results tracking checks the rendered status and verifies it corresponds to the current input, rather than assuming an asynchronous results event belongs to the latest query.

## GTM / GA4 activation requirement

The site code pushes the events above, but a `dataLayer` event alone does not prove that Google Analytics 4 receives it. In Google Tag Manager, configure matching Custom Event triggers and GA4 Event tags (or use an existing approved tag setup), then verify with GTM Preview and GA4 DebugView. This repository change cannot publish or verify a remote GTM container configuration. Until that separate setup is confirmed, report the code instrumentation as implemented and tested—not end-to-end GA4 collection.

## Deliberately out of scope

- Raw search terms in analytics.
- Changes to the existing Microsoft Clarity / GTM setup.
- Robots.txt directives controlling AI crawlers. That is a separate governance decision and remains unchanged.
